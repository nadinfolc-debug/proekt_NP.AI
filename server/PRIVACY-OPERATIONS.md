# Эксплуатация закрытого кабинета

Изменения исходников действуют на публичном сайте только после развёртывания новой версии frontend и backend вместе.

- Задать уникальный длинный пароль ADMIN_PASSWORD в настройках хостинга. Демонстрационный пароль change-me-now не принимается. Никому не передавать пароль; MFA включить у Timeweb, GitHub и почты.
- Для App Platform использовать APPLICATION_STORAGE=s3 и отдельный приватный бакет Timeweb в РФ. Ключи только в серверных переменных S3_ACCESS_KEY_ID и S3_SECRET_ACCESS_KEY, никогда в VITE_*. Предпочтителен отдельный пользователь с чтением/записью только этого бакета. Не включать публичный доступ, CORS, раздачу через домен, версионирование и Object Lock без отдельной процедуры удаления старых версий. Установить лимит исходящего трафика и отключить автопереход на больший тариф. Альтернатива вне App Platform: DATA_DIR на постоянном закрытом томе в РФ вне dist/public. В production локальный файл без явного DATA_DIR не допускается.
- Вход ограничен десятью попытками за 15 минут для всего экземпляра сервера, включая успешные. После перезапуска счётчик сбрасывается. Для нескольких экземпляров нужен общий лимит на reverse proxy. Прокси должен удалять подставленные клиентом X-Forwarded-For перед установкой своего значения.
- Сессия действует 12 часов с момента входа. После выхода токен отзывается. Использовать HTTPS; настроить HSTS на прокси после проверки всех доменов. Новая версия API запрещает кэширование JSON-ответов.
- Новые заявки сохраняют согласие, серверное время и версию; исходник юридических документов архивируется в consent-documents по SHA-256 в приватном S3 (при локальном режиме — в DATA_DIR). При изменении согласия обновлять consentVersion в src/lib/notify.ts и server/src/validate.mjs одновременно. Старым заявкам согласие задним числом не приписывается.
- Новые письма содержат только номер и время. Ранее отправленные полные письма и корзину почты проверить и удалить по применимым основаниям и срокам вручную. SMTP использовать российский с TLS.
- Для каждой цели установить обоснованные сроки хранения и основания продолжения обработки. Регулярно пересматривать завершённые заявки; при достижении цели/отзыве и отсутствии другого основания удалять запись в кабинете. Автоудаление намеренно не включено до утверждения сроков оператором.
- Удаление заявки удаляет запись и связанное подтверждение согласия из рабочей базы. Это не удаляет старые письма, переписку и резервные копии. Установить срок ротации резервных копий в РФ и процедуру удаления/невосстановления удалённых данных. Документировать уничтожение применимым способом. Архивы текстов согласия не содержат данных заявителей.
- Проверить актуальность уведомления Роскомнадзора, цели, категории, местонахождение базы, договоры с хостингом/почтой, порядок обращений субъектов и реагирования на инциденты. Переписку в Telegram оценить отдельно на предмет трансграничной передачи. Эти организационные вопросы кодом не подтверждаются.

Проверка перед запуском: без токена GET /api/applications и /api/auth/me возвращают 401; с произвольным токеном тоже 401; после выхода прежний токен не работает. Проверять только на тестовой базе. Проверить отправку без согласия (400), превышение лимита входа (429), отсутствие ПДн в письме и отсутствие доступа к служебным файлам через HTTP.
