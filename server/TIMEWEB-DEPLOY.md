# Автопубликация GitHub → Timeweb

Репозиторий: https://github.com/nadinfolc-debug/proekt_NP.AI
Ветка публикации: main. Публичный адрес: https://np-aiprikolota.ru

## До включения

Проверить существующее приложение и источник кода в панели Timeweb. Не создавать второе платное приложение вместо существующего.

Заявки сейчас хранятся в JSON-файле на сервере. До пересборки проверить наличие постоянного тома и сохранение server/data. Для нового кода можно задать DATA_DIR как путь к уже смонтированному закрытому постоянному тому. Смена DATA_DIR сама по себе не переносит старую базу. До смены нужно безопасно перенести имеющиеся данные на сервере и проверить резервную копию в РФ. Не скачивать заявки в GitHub.

## Настройки существующего приложения

- Источник — указанный GitHub-репозиторий, ветка main.
- Для корневого Dockerfile — контекст сборки корень репозитория, порт 8080. Не применять эти параметры вслепую к существующему приложению с иным способом запуска.
- Переменные ADMIN_LOGIN, ADMIN_PASSWORD, SMTP_* и NOTIFY_EMAIL остаются только в Timeweb; .env и база в GitHub не отправляются.
- Если frontend и API работают с одного домена, VITE_API_URL не требуется. ALLOWED_ORIGINS должен разрешать фактический адрес сайта.
- Включить «Сборка по последнему выполненному коммиту» (автодеплой) после проверки постоянного хранилища.

## Проверки

GitHub Actions собирает сайт и запускает тесты закрытого кабинета. Корневой Dockerfile также запускает эти тесты до сборки: неуспешная проверка прерывает сборку образа. Сами GitHub Actions не включают автодеплой и не гарантируют ожидание их результата Timeweb — публикацией управляет интеграция App Platform.

После push в main проверить в Timeweb новый commit и успешный статус деплоя. На сайте: /api/health отвечает JSON, /api/applications и /api/auth/me без входа — 401 с Cache-Control: no-store. Проверить кабинет владельцем и наличие прежних заявок. При ошибке восстановить предыдущую версию приложения, не перезаписывая базу.

Документация: https://timeweb.cloud/docs/apps/deployment
