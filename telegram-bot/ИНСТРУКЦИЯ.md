# Инструкция: заявки в Telegram (Turnstile)

Клиентский секрет больше не используется. Защита — Turnstile + серверная проверка.

Продакшен-деплой Worker и замену живой отправки делайте только после отдельного подтверждения. Чеклист: `SECURE_CUTOVER.md`.

---

## Вариант А. Локальный тест

### А1. Файл `telegram-bot/.env`

```
BOT_TOKEN=токен_от_BotFather
CHAT_ID=ваш_chat_id
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA
PORT=8787
```

Dummy secret Cloudflare всегда проходит `siteverify` — только для локальных тестов.

### А2. Запуск сервера

```bash
cd "d:\Вейб - кодинг\Моштабный сайт\telegram-bot"
node local-server.mjs
```

Должно появиться: `NP.AI notify listening on http://127.0.0.1:8787`  
**Это окно не закрывайте**, пока тестируете.

### А3. Подключить сайт

В **корне** проекта (`.env` или `.env.development`):

```
VITE_NOTIFY_URL=http://127.0.0.1:8787
VITE_TURNSTILE_SITE_KEY=1x00000000000000000000AA
```

Не добавляйте secret key Turnstile и `BOT_TOKEN` в `VITE_*`.

### А4. Перезапустить сайт

```bash
cd "d:\Вейб - кодинг\Моштабный сайт"
npm run dev
```

Откройте сайт → блок **«Обсудить проект»** → отметьте Turnstile → отправьте тестовую заявку.  
В Telegram должно прийти полное сообщение от бота.

Админка `/admin` временно отключена; заявки в `localStorage` не сохраняются.

## Вариант Б. Cloudflare Worker (после отдельного подтверждения)

### Б1. Аккаунт Cloudflare

1. Зарегистрируйтесь на https://dash.cloudflare.com/ (если ещё нет).
2. Создайте виджет Turnstile и сохраните site key / secret key.
3. Убедитесь, что установлен Node.js.

### Б2. Деплой

```bash
cd "d:\Вейб - кодинг\Моштабный сайт\telegram-bot"
npm install
npx wrangler login
npm run deploy
```

Скопируйте URL вида `https://npai-telegram-notify.ВАШ_АККАУНТ.workers.dev`.

### Б3. Секреты (не попадают на сайт)

```bash
npm run secret:bot
npm run secret:chat
npm run secret:turnstile
```

### Б4. Подключить сайт

```
VITE_NOTIFY_URL=https://npai-telegram-notify.ВАШ_АККАУНТ.workers.dev
VITE_TURNSTILE_SITE_KEY=<публичный site key виджета>
```

В GitHub Actions: secrets `VITE_NOTIFY_URL` и `VITE_TURNSTILE_SITE_KEY`.

### Б5. Пересобрать и выложить сайт

Переменные `VITE_*` попадают в сайт **только при сборке**. После смены env нужна новая сборка и публикация сайта — **только после вашего подтверждения**.

## Частые проблемы

| Проблема | Что проверить |
|----------|----------------|
| Бот молчит | Написали боту «привет»? Верный `CHAT_ID`? |
| На сайте ошибка Turnstile | Задан ли `VITE_TURNSTILE_SITE_KEY`? Совпадает ли secret на сервере? |
| В TG пусто | Запущен ли `local-server` / Worker? Есть ли `BOT_TOKEN` и `CHAT_ID`? |
| `Too many requests` | Rate limit — подождите окно или снизьте частоту |
| На GitHub Pages не приходит | `VITE_*` заданы **до** сборки? Нужна новая сборка после смены secrets |
| `getUpdates` пустой | Снова напишите боту и обновите страницу |

---

## Важно

- `BOT_TOKEN` и `TURNSTILE_SECRET_KEY` **нельзя** писать в код сайта и в GitHub — только в Worker secrets / `telegram-bot/.env`.
- Файлы `.env` в git не коммитятся (уже в `.gitignore`).
- Старый shared `SECRET` / `VITE_NOTIFY_SECRET` после cutover удалите и при необходимости ротируйте.
